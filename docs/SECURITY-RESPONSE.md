# Реагирование на риск ключа подписи

1. Не публиковать значения ключа, пароля, secret names/contents или диагностические дампы.
2. Не удалять и не заменять основной ключ до инвентаризации уже установленных APK и выбранного канала распространения: это может разрушить in-place update.
3. Production signing вынести из репозитория в защищённое хранилище CI; ограничить окружение, approvals и аудит. Отдельный staging key хранить только в Secrets.
4. Если ключ действительно был общедоступен, считать его скомпрометированным; определить поддерживаемый механизм ротации для фактического канала (Play App Signing либо контролируемая миграция APK).
5. До согласования ротации не выпускать новые production-APK из непроверенной среды. Тестовые сборки должны иметь отдельные application ID/update URL/Firebase и постоянную staging-подпись.

Этот документ — план; он не утверждает, что ротация или очистка истории выполнены.
