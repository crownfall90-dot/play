# Задания для агентов-исполнителей (очередь, 31.10.2026)

**Роль Claude с этого момента — ревьюер:** он не пишет код, а проверяет сделанное и отвечает вердиктом «принято» или «переделать, потому что…», а также выдаёт следующий промт. Исполнители (Antigravity и другие) берут задания **строго по порядку**, один PR на задание.

Общие правила для каждого задания: прочитай `docs/product/README.md` и `docs/product/AGENT-PROMPT.md`; ветка `dev/stage2-account-network-20261029`; перед коммитом `npm run build && node --test tests/*.test.cjs` (сейчас 137 тестов, все зелёные, golden-партии менять нельзя); тексты в игре по-русски; секреты и токены никогда не писать в репозиторий; выпуск делает только Claude по команде владельца.

## Как сдавать работу
В `docs/coordination/HANDOFF.md`, раздел «От Antigravity → Claude», напиши: номер задания, ссылка на PR, что сделано (по пунктам критериев ниже), как проверено (команды и скриншоты 390×844), что **не** проверено, риски. Claude ответит в разделе «От Claude → Antigravity».

**Вердикт «принято»** — все критерии выполнены, тесты зелёные, нет регрессий. **«Переделать»** — с перечнем: что не так, почему (воспроизведение или ссылка на строку), что ожидается.

## Задание 1. Удержание D1/D7 в панели владельца (H-2) — приоритет P0
**Зачем:** без этого нельзя понять, возвращаются ли игроки. События уже пишутся (выпуск 1.0.241): `first_open`, `first_game_done`, `second_game_done`, `third_game_done`, `return_d1`, `return_d3`, `return_d7`, `save_prompt_tap`, а также `game_start`, `game_end`, `open`, `login`, `sign_up` — в журнал игрока `/logs/{uid}` (см. `plog`/`LOG_KINDS` в `web/game.html`) и в Firebase Analytics.
**Сделать:** в панели владельца (скрытая в игре — 7 касаний по «Версия» в настройках; и страница `/play/admin/`, см. `web/` и `tools/`) добавить блок «Удержание»:
- сколько новых игроков за последние 14 дней (по `first_open`);
- доля вернувшихся на 1-й, 3-й и 7-й день (из `return_d1/d3/d7`), по дням-когортам;
- воронка: открыли → сыграли 1-ю → 2-ю → 3-ю партию → сохранили профиль;
- числа без персональных данных (никаких имён и почт), не больше одного запроса к базе на открытие блока (ограничить выборку, не читать всю базу).
**Критерии:** блок виден только владельцу (проверить, что обычный игрок его не открывает: тест вроде `tests/owner-panel-gate.test.cjs`); работает при пустых данных («пока нет данных»); тест с моком Firebase (тесты **никогда** не пишут в боевую базу); скриншот блока.
**Подсказка по ограничениям:** платный Firebase Blaze не берём, серверных функций нет — считать на клиенте панели из `/logs` с лимитом; если выборка слишком тяжёлая, предложить в PR другой способ и объяснить, а не молча урезать.

## Задание 2. Боты-«соседи» в быстрой онлайн-игре (H-5) — P1
Если живой соперник не найден за ~10 секунд, подставить бота с честной пометкой «бот»; игрок не остаётся в пустой комнате. Кубки за партию с ботом не начислять (иначе накрутка). Файлы: подбор соперника в `web/game.html` (`quick`, лобби). Критерии: тест с мокнутой сетью; пометка видна всем; нет утечки ботов в настоящие комнаты друзей.

## Задание 3. Баланс: сила ботов и задания для коротких партий (G-1, G-4/S-5) — P1
Симуляция: 3 уровня ботов друг против друга по 200 партий в режимах 30/50/100 карт; отчёт в `docs/product/` (кто сколько выигрывает, средний счёт, длительность). Затем пересчитать пороги заданий (`QUESTS`, `src/state/progress.js`) под партии в 30 карт. Критерии: отчёт с цифрами; тесты `state-progress`; golden-партии не менялись.

## Задание 4. Причины возвращаться (R-5, R-12, R-7, R-6, R-8) — P1, по одному PR
R-5 плашка заданий на главной; R-12 «заморозка серии» (один пропуск в неделю); R-7 недельные цели с сундуком; R-6 сезоны лиги (правила Firebase обновить в `docs/firebase-rules.json` и **предупредить владельца**, он публикует их сам); R-8 рейтинг среди друзей. Подробности и указатели — `docs/product/BACKLOG.md` раздел B. Критерии каждого: тест, скриншот, запись в `release-notes.md` только для игроков.

## Задание 5. Социальное: реванш и приглашение одним касанием (N-5) — P1
После партии кнопка «Реванш» (те же игроки и режим, один тап); приглашение друга ссылкой с кодом комнаты в одно касание из итогов. Критерии: работает онлайн и с друзьями; тест на двух клиентах с моком.

## Задание 6. Дизайн D-1 — P2
Привести к стилю «Пазл-мозаика» (`docs/design/STYLE.md`) остаток: игровое поле (рамки, плашки), поиск соперника, итоги партии, карточки магазина. Критерии: скриншоты до/после на 390×844 и 360×740; без новых цветов вне палитры; тесты зелёные.

## Задание 7. Безопасность и надёжность (S-3, M3, S-7) — P2
S-3 очистка старых комнат и рост базы; M3 публичные PIN и промокоды (убрать чтение из публичного доступа или сузить правилами); S-7 Firebase App Check (подготовить код, включение — решение владельца). Изменения правил — только предложением в `docs/firebase-rules.json` и пометкой для владельца. Критерии: описание риска до/после, тесты, откат.

## Задание 8. Разбор монолита `web/game.html` (E-1.1…E-1.13) — P2, долгий
По одному модулю за PR по рецепту `docs/product/MONOLITH-PLAN.md`; порядок: оболочка и обновления → вход через Google → аккаунт и синхронизация → комнаты/друзья/присутствие/подбор. Критерии: поведение не меняется, golden-партии без изменений, размер `game.html` уменьшается, модуль имеет тесты.

## Задание 9. Google Play (H-3) — P3, только после выпуска «B» (новый ключ подписи)
Карточка магазина, скриншоты, 15-секундное видео, политика конфиденциальности, закрытое тестирование. Выпуск «B» делается по отдельной команде владельца (`docs/SIGNING-KEY-ROTATION.md`).
