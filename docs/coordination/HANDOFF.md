### 2. Что я исправил и запушил

1. **`docs/firebase-rules.json` — критично.** Правило «админ = `auth.token.email != null`» пускало *любого игрока с сохранённым профилем*: он мог включить техработы для всех, создать промокод на любое количество золота и читать `/errors` и `/feedback`. Теперь админ — только тот, у кого в базе `admins/{uid} === true`; узел `admins` никто не может читать или писать из клиента. Добавлена валидация `config/maintenance` (bool + текст ≤ 500), `promo_codes` (`gold` 1…1000), `errors` (только создание, `ts === now`, лимиты полей).
2. **`web/game.html` — stored XSS.** `showMaintenanceScreen` вставлял сообщение из базы через `innerHTML`; вместе с п.1 любой игрок мог выполнить JS у всех игроков. Теперь сообщение вставляется как `textContent`. Тест расширен (`<img onerror>` не должен попасть в разметку).
3. **`web/game.html` — `contextmenu`.** Глобальный `preventDefault` убирал long-press меню в полях: нельзя было вставить код друга, почту или пароль. Теперь меню остаётся в `input`, `textarea` и `[contenteditable]`.
4. **`promote-production.yml` + `android.yml` — номер версии.** `CODE=100+GITHUB_RUN_NUMBER` считается *отдельно для каждого workflow*: первый запуск promote дал бы `v101` (тег уже есть, а Android не ставит версию с меньшим versionCode). 5. **`promote-production.yml` — инъекция в shell.** `${{ inputs.notes }}` подставлялся прямо в скрипт; теперь через `env: NOTES`.

### 4. TASK-008: архитектура перехода на Vite

**Главные ограничения** (нарушать нельзя):
- **Детерминизм онлайна.** Все телефоны строят одну партию из `cfg` (deck, seed) и ходов. Любое изменение порядка `rng()`, итерации `Map` или `TYPES` = «партия разошлась» между старой и новой версией. Протокол сообщений (`t: move/start/hello/...`) не меняется.
- **Android грузит `file:///android_asset/index.html`.** ES-модули через `file://` в WebView ненадёжны (CORS) → сборка **в один HTML-файл** (`vite-plugin-singlefile`), как сейчас.

Правила: дописывать может только сам игрок, читать и чистить — админ (`docs/firebase-rules.json`). Ошибки теперь несут `uid` (индекс `errors/.indexOn uid`). Админ читает `profiles/{uid}` (уровень, золото, статистика).
- **Панель** (`tools/founder-admin.html`): карточка «Игроки и логи» — список из `/presence` (500 последних), поиск, карточка игрока (устройство, версия, кубки, уровень, золото, партии, обращения), журнал, ошибки игрока, «Скопировать», «Очистить», общий список последних ошибок. Тесты `tests/admin-players.test.cjs`, `tests/player-log.test.cjs`.
- **ВАЖНО для владельца:** правила нужно опубликовать заново (Firebase Console → Realtime Database → Rules → вставить `docs/firebase-rules.json` → Publish), иначе журналы не будут записываться, а панель не прочитает профили.
- **Окно «Очки и правила»** (`helpWindow()`, кнопка `#helpBtn` в шапке партии): очки за город/дорогу/крепость/мост и что сделать, фишки, респект, правила; данные партии (режим, фишек, ничья) берутся из `gameRules`. Тест `tests/help-window.test.cjs`.

## Нагрев телефонов (Claude, 31.10)

- **Замер** (`CDP Performance.getMetrics`, доска 52 карты с рекой и озёрами, ход игрока, без касаний): 0,107 с работы на секунду, 17 бесконечных CSS-анимаций, ~62 пересчёта стилей в секунду. Источник — вода: `fallX/fallY` и `lakeFlow` двигают фон (перерисовка каждый кадр), `lakeFlow` ещё с `mix-blend-mode: screen`, `foam`. Без воды на доске — 0,015.
- **Сделано:** (1) анимации воды идут шагами (`steps()`, ~10 к/с вместо 60); (2) «покой»: через 3,5 с без касаний и ходов (`wake()` в game.html) на `<html>` класс `calm` — `animation-play-state: paused`, просыпается от касания и в `startTurn()`; (3) пока палец двигает поле (`.board.dragging`) вода стоит; (4) `setClock` меняет DOM только при смене текста. **После:** в покое 0,019 с/с (в 5,6 раза меньше), при постоянных касаниях ~0,09 (на 25 % меньше).
- **Не мерил:** GPU на реальном телефоне (в headless нет GPU-композитинга). Если жалобы на нагрев останутся — следующие подозреваемые: число слоёв в 3D-сцене (~200 спрайтов-билбордов), `backdrop-filter` на плавающих панелях, музыка (WebAudio) — снимать на устройстве через `chrome://inspect` → Performance.
