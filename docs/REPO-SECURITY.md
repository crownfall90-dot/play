# Репозиторий и данные игры: как защищено и что включить владельцу

## Что уже сделано в репозитории
- **Лицензия «Все права защищены»** (`LICENSE`): код, графику, звуки и тексты нельзя копировать, распространять и использовать без разрешения; нельзя делать неофициальные клиенты и обращаться к серверам игры в обход официальных сборок. Это юридическая защита: при копировании — жалоба DMCA в GitHub / в магазин приложений.
- **README** — официальная страница игры (играть, скачать, политика, поддержка); внутреннее — под спойлером.
- **SECURITY.md** — как сообщать об уязвимостях приватно.
- **CODEOWNERS** — любое изменение требует ревью владельца (работает вместе с защитой веток, см. ниже).
- **Шаблоны Issues** — только «Ошибка в игре», пустые Issues выключены, уязвимости — приватно.
- **`.gitignore`** — ключи, пароли, сертификаты и файлы сервисных аккаунтов никогда не попадут в git.
- Удалены одноразовые устаревшие workflows (выпуски 210–213 и временные проверки), которые использовали старый ключ.
- **Ключ подписи** переводится на новый, хранящийся только зашифрованным (`docs/SIGNING-KEY-ROTATION.md`).
- **Онлайн-комнаты** принимают ходы только от владельцев мест (`netAuth`), правила базы требуют подлинного автора.

## Важно понимать
Публичный репозиторий **можно прочитать и скачать** — это не скрыть никакими настройками. Защита строится так:
1. **Юридически** — лицензия запрещает копирование и использование (основание для удаления копий).
2. **Технически** — ничего ценного в репозитории нет: секреты только в GitHub Secrets, ключ подписи зашифрован, данные игроков — в Firebase за правилами доступа, а не в коде.
3. **Данные игры** (профили, рейтинг, комнаты) защищены правилами Firebase (`docs/firebase-rules.json`): читать чужой профиль нельзя, писать можно только своё; рост кубков ограничен.

## Что включить владельцу в настройках GitHub (5 минут)
**Settings → Branches → Add rule** для `main`:
- Require a pull request before merging (+ Require review from Code Owners).
- Require status checks to pass (Test APK, Account regression, Android compile check).
- Do not allow force pushes, do not allow deletions.

**Settings → Code security**:
- Secret scanning **и Push protection** — GitHub не даст запушить токен или ключ.
- Dependabot alerts.
- Private vulnerability reporting — включить (для кнопки «Report a vulnerability»).

**Settings → Actions → General**:
- Workflow permissions: **Read repository contents** по умолчанию (наши workflows сами просят нужные права).
- Fork pull request workflows: требовать одобрение для всех внешних участников.

**Settings → Collaborators**: доступ на запись только тем, кому нужен; у всех — двухфакторная аутентификация. Включить 2FA и на Google-аккаунте Firebase.

## Сильнее (по решению владельца)
- **Firebase App Check** (бесплатно): сервер принимает запросы только от официального приложения (Play Integrity) и сайта (reCAPTCHA). Это закрывает доступ к базе «самописным» клиентам и скриптам даже с публичным ключом Firebase. Задача S-7 в BACKLOG (код + включение в консоли).
- **Закрытый исходный код**: перенести разработку в приватный репозиторий, а сборки (Releases, `latest.json`) и сайт публиковать в отдельный публичный репозиторий только с готовыми файлами. Нужны: новый публичный репозиторий, токен с правом записи в него как секрет (заводит владелец сам), смена `UPDATE_REPO` в приложении — делать вместе с выпуском «B» смены ключа, чтобы игроки переставили приложение один раз. Задача S-8.
