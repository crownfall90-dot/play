## Отложено — пуши (обсудили, ждут решения владельца)

**А. Веб-пуш (iPhone с игрой на экране «Домой», iOS 16.4+, и браузеры)**
- Что нужно от владельца в консоли Firebase:
  1. Project settings → General → Your apps → Add app → Web (</>), без Hosting → прислать `appId` (`1:467929090444:web:…`).
  2. Project settings → Cloud Messaging → Web Push certificates → Generate key pair → прислать публичный ключ (Key pair).
  Обе строки публичные; ключ сервис-аккаунта никогда не присылать.
- План: firebase-messaging в веб-сборке (сервис-воркер `sw.js` + `onBackgroundMessage`), токен в `/webpush/{uid}` (правило: пишет только владелец), `news.yml`/`fcm-send.py --news` дополнительно рассылает по веб-токенам (читает их сервис-аккаунтом), просрочённые токены удаляет. Кнопка «Включить уведомления» в веб-настройках (на iPhone — только в установленной игре).

**Б. Пуш «Друг зовёт играть», когда игра закрыта**
- Нужен сервер, который отправит пуш сразу при появлении `/inbox/{uid}/{from}_r`. Варианты:
  - **Firebase Blaze + Cloud Functions** (рекомендуется): триггер `onValueCreated('/inbox/{uid}/{key}')` → FCM на токены получателя. Нужна карта; бесплатных лимитов хватает с запасом, поставить бюджет-лимит 1 $. Выкладка — через GitHub Actions (секрет сервис-аккаунта уже есть).
  - **Cloudflare Workers** (бесплатно, без карты): клиент отправляет приглашение через Worker, тот проверяет Firebase ID-токен и шлёт FCM. Нужен аккаунт Cloudflare и API-токен для выкладки (секрет в GitHub).
  - Без сервера (фоновая проверка раз в ~15 мин, только Android) — не рекомендуется: приглашение живёт 15 минут.
- В любом варианте: Android сохраняет FCM-токен в `/push/{uid}`, `PushService` обрабатывает `type: "invite"` — уведомление «X зовёт играть», нажатие открывает игру сразу в комнате.
