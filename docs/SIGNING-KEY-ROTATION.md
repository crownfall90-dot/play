# Смена ключа подписи Android-приложения (2026-10/11)

## Почему
Старый ключ `app/release.keystore` лежит в репозитории, и пароль к нему — значение по умолчанию из `app/build.gradle` (проверено: `keytool -list -storepass mosaic-kingdom` открывает его). Любой, у кого есть доступ к репозиторию, может подписать APK так, что Android примет его как **обновление** игры у игроков. Ключ считается скомпрометированным навсегда (он остаётся в истории git).

Android не ставит обновление, подписанное другим ключом, поверх установленного приложения. Поэтому игрокам с APK с GitHub нужно **один раз переустановить** игру. Прогресс переносится через профиль (облачная синхронизация `/profiles/{uid}`): после установки достаточно войти в тот же профиль.

## Как устроено
- **Новый ключ** создаёт `.github/workflows/rotate-signing-key.yml` на раннере GitHub (RSA 4096, PKCS12, случайный пароль). В репозиторий попадает только `app/signing/release.p12.enc` — архив «ключ + пароль», зашифрованный AES-256 (PBKDF2, 600 000 итераций) секретом `SIGNING_PASSPHRASE` (если его нет — `BACKUP_PASSPHRASE`). Отпечатки сертификата (публичные) — в `app/signing/release-cert.txt`. Ключ никогда не перезаписывается.
- **Сборки** (`promote-production.yml`, `android.yml`) вызывают `scripts/ci/signing-key.sh`: пока нет файла `app/signing/USE_NEW`, подписывают старым ключом; с ним — расшифровывают новый во временную папку раннера и отдают Gradle через `KEYSTORE_FILE/…`, а в `latest.json` пишут `"cert"` — SHA-256 сертификата.
- **Приложение** (`app/src/github/…/Updater.java`) сравнивает `cert` из `latest.json` со своей подписью; если отличается — игра показывает окно «Новое приложение Puzzlegrad» (`reinstallDialog` в `web/game.html`): 1) сохранить прогресс (вход/создание профиля), 2) скачать новый APK (в «Загрузки» через браузер), 3) открыть настройки приложения → «Удалить», 4) установить скачанный файл и войти. Окно показывается при каждом запуске, пока игрок не переустановит; старая копия продолжает работать. События `reinstall_offer/_download/_remove` видны в журнале панели владельца.
- `android-compile.yml` компилирует Java всех вариантов при каждом изменении `app/**` — ошибка Java не доедет до выпуска.

## Шаги

### Фаза 0 — подготовка (сделано в ветке)
Код приложения и CI; файл `app/signing/ROTATE` запускает создание ключа, результат — коммит `ci(signing): новый ключ подписи (зашифрован)` с `release-cert.txt`.

### Владельцу (один раз, до фазы 2)
1. **Добавить SHA-1 нового ключа** (из `app/signing/release-cert.txt`) в Firebase → Настройки проекта → Android-приложение `com.crownfall.mosaic` → «Отпечатки сертификата SHA». Старый SHA-1 **не удалять** до конца перехода. Без этого вход через Google в новом приложении не сработает (вход по почте работает всегда).
2. **Сохранить `BACKUP_PASSPHRASE`** (или завести отдельный `SIGNING_PASSPHRASE` и попросить агента перешифровать) в менеджере паролей: без него новый ключ не расшифровать и приложение больше нельзя будет обновить.
3. Скачать и надёжно сохранить копию `app/signing/release.p12.enc` вне GitHub.

### Фаза 1 — выпуск «A» (старым ключом)
Обычный «Выпускай». Версия ставится поверх как обычно и уже умеет показывать окно переустановки. Подождать 1–3 дня, чтобы большинство игроков открыли игру и обновились (копии старше «A» окно показать не смогут — им поможет push и текст заметки).

### Фаза 2 — выпуск «B» (новым ключом)
1. Создать `app/signing/USE_NEW`, удалить из репозитория `app/release.keystore`, убрать пароли по умолчанию из `app/build.gradle`.
2. В `release-notes.md` — строка для игроков: «Игру нужно один раз переустановить: откройте её и следуйте шагам, прогресс сохранится в профиле».
3. «Выпускай». Push-уведомление уйдёт всем; копии «A» покажут окно переустановки.
4. Через 2–4 недели — удалить старый SHA-1 из Firebase.

## Ограничения
- Гостевой прогресс (без профиля) при переустановке не переносится — поэтому шаг 1 окна просит войти/создать профиль и предупреждает при удалении без профиля.
- Копии старше «A» при попытке обновиться получат от Android «Приложение не установлено»; им нужно удалить игру вручную и установить с сайта/GitHub.
- Откат (`android.yml` с `rollback`) на версию до этой смены собрал бы старым ключом — после фазы 2 откатывать только версии с этой поддержкой.
- Вариант Google Play не затронут: там подпись делает Google (Play App Signing), загрузочный ключ — отдельный.
