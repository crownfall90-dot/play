## Коротко о проекте

Puzzlegrad — мобильная настольная игра в стиле «Каркассона»: игроки по очереди выкладывают карты-пазлы (города, дороги, реки, крепости), ставят фишки и получают очки за достроенное. Есть игра с ботами, на одном телефоне, онлайн (быстрая игра на кубки) и комнаты для друзей. Android-приложение (APK с GitHub и в будущем Google Play), веб/PWA на GitHub Pages, iPhone — через веб.

Репозиторий `crownfall90-dot/play`, рабочая ветка `dev/stage2-account-network-20261029`, релизы — тегами `vNNN` (версия `1.0.NNN`).

## Правила работы (владелец утвердил)

- Выпуск делается **только по команде владельца** («Выпускай»): слияние PR в `main` → запуск `promote-production.yml` на `main` → после успеха `python3 scripts/changelog.py` (предварительно `git fetch --tags`), очистить `release-notes.md`, влить PR с журналом.
- `release-notes.md` — только строки для **игроков** (без панели владельца, токенов, CI, скриптов).
- Перед коммитом: `npm run build` и `node --test tests/*.test.cjs` (сейчас ≈130 тестов, все зелёные). Тесты, падающие только при параллельном запуске, — признак хрупкого теста: чини тест, не отключай.
- Формат коммитов `тип(область): описание`; в `main` напрямую не писать; без force-push; секреты (`FIREBASE_SERVICE_ACCOUNT`, токены GitHub) у владельца не просить.
- **Платный Firebase Blaze не берём** → нет Cloud Functions → нет серверной проверки результатов/наград. Всё, что требует доверенного сервера, помечено в BACKLOG как «ждёт решения».
- Тестовые клиенты **полностью мокают Firebase** и никогда не пишут в боевой `/presence`.
