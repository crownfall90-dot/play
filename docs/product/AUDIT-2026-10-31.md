## 🔴 Высокие

### H1. Подписной ключ приложения лежит в репозитории с паролями по умолчанию
**Статус: смена ключа запущена** — план и шаги в `docs/SIGNING-KEY-ROTATION.md` (новый ключ создаётся в CI зашифрованным, приложение само проводит игрока через переустановку; пароль по умолчанию действительно открывает старый ключ — проверено).
`app/release.keystore` отслеживается git (с первого коммита `97fbcad`), а `app/build.gradle` подставляет пароли по умолчанию `mosaic-kingdom` (хранилище и ключ), алиас `mosaic`. Если репозиторий публичный, любой может собрать приложение, подписанное **тем же ключом**, и Android примет его как обновление установленной у игроков игры; канал обновлений идёт с GitHub Releases. Это самая серьёзная проблема.
Что делать (решает владелец): выпустить **новый** ключ, хранить его только в GitHub Secrets (`KEYSTORE_*`), убрать пароли по умолчанию и сам файл из репозитория (`git rm`), в Google Play использовать подпись Play App Signing (ключ загрузки отдельно). Цена: игроки с APK с GitHub после смены ключа должны один раз переустановить (подпись изменится). Из истории git файл не исчезнет — старый ключ считать скомпрометированным.

### H2. В логе комнаты нет автора сообщений — любой с кодом комнаты может ломать чужую партию
**Статус (31.10, вечер): исправлено на стороне клиента** (`netAuth` в `web/game.html`, тест `tests/net-auth.test.cjs`); чтобы защита работала, владелец должен **опубликовать обновлённые правила** `docs/firebase-rules.json` (поле `u` обязано совпадать с `auth.uid`). Партии, начатые новой версией (`start.sec = 1`), «защищённые»: сообщения без `u` и от чужих аккаунтов игнорируются; старые партии работают как раньше.
Правила: `rooms/$code/msgs/$id` — запись любому вошедшему пользователю, без проверки автора. Любой, знающий код (или участник), может отправить `move`/`resign`/`start`/`host` за любое место. Неверный ход (`pumpRemote`) показывает «Партия разошлась между телефонами» и **останавливает партию у всех**: восстановления нет. Также подделывается `peek` (только вид).
Что сделано/делать: добавить в каждое сообщение поле `u` = uid автора, в правилах требовать `newData.child('u').val() === auth.uid`, а клиент должен принимать `move`/`resign` только от владельца места (`players[p].uid`); сообщения не от владельца игнорировать, а не останавливать партию.

### H3. Награды и рейтинг доверяют клиенту (известное ограничение)
`profiles/{uid}.w` (золото, всё) пишет сам игрок; кубки ограничены «+30 раз в минуту», но этого хватает, чтобы за час накрутить тысячи. Владелец решил не брать Firebase Blaze, поэтому серверной проверки нет. Пока не выдавать настоящих призов за рейтинг; для сезонов — только косметика (см. RETENTION.md R-6).

## 🟠 Средние

### M1. База растёт без ограничений
`rooms/{code}/msgs` не чистятся никогда; `peek` добавляет несколько записей на ход (≈ 3–6), `errors`, `logs`, `feedback` тоже копятся. Что делать: ночная задача GitHub Actions (по образцу `backup-database.yml`, учётная запись сервиса) удаляет комнаты старше 7 дней и старые логи; `peek` вынести из лога в «живой» узел `rooms/{code}/peek/{место}` (перезапись, не добавление) — нужны правила и публикация владельцем.

### M2. Резервное копирование Android включено — **исправлено** (`allowBackup="false"`)
`android:allowBackup="true"` — автоматическая копия данных приложения (в том числе локального хранилища WebView с токеном входа) уходит в облако Google и может переехать на другой телефон. Поставить `false` или описать `dataExtractionRules`.

### M3. Закрытая тестовая сборка защищена публичным PIN
`config/testerPin` читается всеми (`.read: true`); `promo_codes/$code` читается любым вошедшим. PIN — не защита, а «заслонка»; промокод может проверить любой, кто угадал код. Если нужна настоящая закрытость, брать PIN из защищённого узла с правом чтения только у вошедших тестеров и ограничить число проверок.

### M4. Задания и достижения не пересчитаны под короткие партии
По 24 пробным партиям: «Быстрая» 2 игрока — 8–15 очков на игрока, «Классика» 2 игрока — 27–40, 5 игроков — 7–30. Задания «Наберите 30 очков за одну партию» и «Заработайте 50 очков за день» теперь достижимы почти только в Классике 1×1. Пересчитать пороги (BACKLOG G-4) и убедиться на симуляции.

### M5. Сила уровней ботов не измерена
Уровни работают и доигрывают партии без ошибок, но «обычные сильнее лёгких, сложные сильнее обычных» не доказано (BACKLOG G-1).

### M6. Автоматизация `account-verify` пушит в рабочую ветку — **смягчено** (повтор с `git pull --rebase`)
Последний шаг коммитит отчёт в `dev/stage2-account-network-20261029` и падает с `rejected (fetch first)`, когда параллельно пушит человек. Красная проверка вводит в заблуждение. Лучше сохранять отчёт артефактом или пушить в отдельную ветку.

### M7. Время на клиенте для серии дней и заданий
День считается по часам телефона: можно перевести часы и забирать подарок/серию. Принято (нет сервера); смягчить: сверять с серверным временем при онлайне (`.sv timestamp`).
